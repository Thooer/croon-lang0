# 先例

全部待核验：名称、链接、行为来自网页端 LLM 的搜索报告或记忆，只作 Lang0 的实现线索。

## Python、AST 与求值器

| 先例 | 观察 | 与 Lang0 的关系 |
|---|---|---|
| CPython ast 与 symtable | AST 贴近 Python 语法，带源码位置；作用域有明确规则 | Surface 借用 Python 写法，构造检查在 AST 上做 |
| RestrictedPython；pysandbox | 语言层限制不能独立承担沙箱保证 | Lang0 的限制是纵深防御，隔离由独立单元承担 |
| Monty；Ouros | 为运行 Agent 设计的 Python 子集，自己的字节码 VM，可在宿主函数处挂起 | 对照：Lang0 自己规定子集、挂起状态和资源计量 |
| Starlark | 类 Python 写法，确定地算出要做什么，默认无 I/O | 算与做分工的先例；Lang0 仍保留 Python 先验 |
| Lisp 元循环求值器 | 求值器可作为数据表达，区分对象程序环境与运行器 | 支持研究 Language 的递归形状；不能推出隔离或问责 |
| CPython、RustPython、QuickJS 等嵌入式引擎 | 引擎自身会带入未列出的语义、运行时和构建差异 | 不把现成引擎作为 `lang0@1` 的语义来源 |

## 确定性与资源

| 先例 | 观察 | 与 Lang0 的关系 |
|---|---|---|
| Temporal | 控制流交给宿主语言；重放按命令序号匹配，要求代码确定；改代码按版本分支 | Atom、键、恢复和 Definition 中的 Language |
| Erlang BEAM reduction；Lua debug hook | 可以按计算步骤让出和限制执行 | Lang0 按 Surface 运算计步，不按宿主指令计 |
| wasmtime fuel；EVM gas；starlark-go 执行步数 | 同样程序与上限总在同一处停下；底层计量可能随实现变化 | Surface 资源和宿主兜底分开，后者不进入语义 |
| FoundationDB Flow；madsim；rr | 时间、随机、调度和 I/O 使用可记录的确定来源 | Lang0 不读世界，测试用录下的提供者结果回放 |
| Scheme call/cc | continuation 可在任意点保存 | Checkpoint 需要把求值状态保存为数据 |

## 隔离与 WASM

| 先例 | 观察 | 与 Lang0 的关系 |
|---|---|---|
| WASM、WASI | 可把代码放入受限模块，宿主控制导入和资源 | Lang0 WASM 只导入受控读取，禁止 I/O、时钟、随机数和线程 |
| wizer | 可以预初始化 WASM 模块，减少启动成本 | 可能优化装载，不改变 Language 语义 |
| CPython 嵌入 WASM、Go、OCaml、AssemblyScript | 运行时、GC、线性内存快照和版本耦合会改变隔离与恢复成本 | WASM 只承担隔离，不决定 Surface 语义 |
| 证明携带代码、DeCI、解释器塔 | 运行前验证不可信代码或用另一层解释器约束实现 | 这是未来 Language 方向，当前 Kernel 不在运行前验证 Language |
