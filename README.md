# croon-lang0

`croon-lang0` 实现 `lang0@1`，Croon 的第一种 Language。

在 Croon 里，一个 Agent 的做法写成一段程序，放在它的 Definition 里；W0 在运行中造出新的 Agent，写下的也是这样一段程序。lang0 就是写这些程序的语言。它的写法是 Python 3.12 的一个子集，求值是确定的，每一步计算都有账可查，正式运行时关在一个 WASM 模块里。

## 为什么需要一种语言

一个自然的问题是：为什么不直接让模型写 Python？

原因在 Croon 对求值的要求。崩溃之后，内核要把一个 Instance 的程序重新跑一遍，凭 Journal 里记下的结果，把它带回崩溃前的那一刻。这要求同一段程序面对同样的结果，每一次都走出同样的步子。它还要求程序碰外部世界的唯一途径是 Port，否则内核记不下、拦不住，也恢复不了。真正的 Python 两样都做不到：时间、随机数、内存地址、哈希决定的顺序，都会让两次运行分道扬镳；`open` 与 `subprocess` 则让程序绕过 Port，直接对世界动手。

## 为什么是 Python 的写法

另一条路是新造一门语言，把这些问题从根上避开。可模型没见过它，只能照着相似的写法去猜；猜错一处，就要靠提示或报错补一处，这样的补丁很难打完。

所以 lang0 反过来，把模型的先验当作最便宜的文档。它不自造关键字，`TypedDict`、`Literal`、f-string、推导式、闭包、`try/except` 都照 Python 的样子写，子集之内的语义也与 Python 相同。真正与 Python 不同的，只有 Python 给不了我们的那几样：交出与取、引用值、键，以及资源的计量。写法像 Python、语义却悄悄不同的构造，我们宁可拦下，因为那样的错误既不报错，也无从补救。

拦下的时候，报错说用什么代替，而不只是说不许。写 `.lower()`，会被告知子集里有哪些字符串方法；写 `set()`，会被告知用 dict 的键来代替。这件小事在实验里看得出分量：在 croon-app 的实测中，报错加上「用什么代替」之后，受影响的任务里构造失败的次数从 7 次降到了 2 次。样本很小，方向是清楚的。

## 确定，而且有边界

lang0 定死了 Python 里随运行变化的东西：没有时钟，没有随机数；默认的 repr 不带内存地址；迭代的顺序只取决于插入的先后，不取决于哈希；回收的时机不影响任何结果；异常的消息文本由 lang0 自己列出，不随某个 Python 构建变化。

它同时给每一次求值记三笔账：步数、调用深度、活着的数据量。三笔账都按程序本身的运算来数，与它跑在哪台机器、用哪种实现无关，超不超限因此也是确定的。超限是一次普通的失败，可以接住，但接住之后也空转不了，下一步账还是超的。所以一段 lang0 程序不会困在一段既不交出、也不结束的计算里。

为了确认子集之内的语义真的与 Python 相同，我们拿 CPython 3.12 做差分对照：同一段程序在两边结果不同，要么是求值器错了，要么是一处已经列明的差异。

## 引用值

在 lang0 里，权利以引用值的样子出现。它和别的值一样，可以作为参数传给函数、存进变量、放进 dict；但它没有字符串形式，对它 `repr` 或者把它编码成 JSON 都会失败，它也不能按名字从一段字符串里被找出来。一个函数能碰到哪些权利，在源码里一眼看得到：它的参数，加上它从外层函数捕获的局部变量。

这让提示词注入失去了最直接的抓手。模型可以被一段文本说服，写下 `exec` 这几个字母，但字母只是字母：Required port 不能按数据查找，写出名字换不来权利。

## 签名就是接口

一个 lang0 程序的入口是 `main`。它的参数与 docstring 在构造时从语法树里读出，就是这个 Agent 对外的 Interface：值类型的参数进 Signature，Port 类型的参数是它需要别人接上的 Required port，Inbox 类型的参数是它向外提供的 Provided port。`croon.tool` 用同样的方式把一个普通函数变成模型能调用的工具，参数的类型就是工具的输入 Schema。整个过程不运行任何代码。

croon-app 里，W0 造出来的 Agent 能直接当成工具调用，靠的就是这一条：接口不必另写，它就是程序自己的签名。

## 隔离

正式运行时，lang0 的求值器是一个不开 WASI 的 WASM 模块：没有文件系统，没有网络，没有时钟，也没有随机数。它唯一从宿主导入的是一个受控的读取，只读得到这个 Instance 被明确交付的内容。模块之外，宿主再加一层燃料、内存与超时的限制。即使求值器自己出了错，停下的也只是这一个 Instance，修好之后沿着 Journal 重开。

## 以后

Language 在 Croon 里是一个插口，lang0 只是插上去的第一种。声明式的工作流、为某类任务专门设计的写法，都可以作为新的 Language 接进来，写出的 Definition 与 lang0 写的一样构造、实例化，受同一套权利约束。再往远处看，一个主体可以写出一种语言，交给另一个主体去用，而不必经过根来安装。这件事还在 Kernel 的待定里，没有定下做法。

## 现在

`lang0@1` 的首版子集与语义正在冻结。顺序求值、CPython 差分、资源计量、WASM 隔离与恢复已经实现，并有测试覆盖；并发的分支与缩短重放的 Checkpoint 还没有。已经发布的语义只增不改：要改变既有程序的含义，就开一个新的 Language 版本，旧版本留着，直到不再有 Instance 使用它。

## 开发

本仓库是独立的 Cargo workspace，通过路径依赖并排放置的 `../croon`。WASM 桥的测试要先构建 guest，命令在 `docs/Engineering.md`；CPython 差分要有 `python3.12`。

文档入口是 `docs/README.md`：写法、类型、Port 与交出在那里，首版清单在 `docs/Subset.md`，语义与资源在 `docs/Evaluator.md`，实现与隔离在 `docs/Engineering.md`。
